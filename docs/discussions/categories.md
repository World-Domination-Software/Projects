# GitHub Discussions – Categories Guide

This document describes the full structure of GitHub Discussions categories for the World Domination Software Projects repository. It serves as both a reference for community members and a setup guide for maintainers configuring or updating discussion categories.

---

## Global categories

These categories span all WDS applications and cover cross-cutting topics.

| Category | Slug | Purpose |
|---|---|---|
| Announcements | `announcements` | Official announcements from WDS. Maintainer-only posting; community can react and comment. |
| Roadmap | `roadmap` | High-level roadmap themes and milestone discussions. See the [Roadmap How-To](ROADMAP-HOWTO.md) for guidance. |
| General | `general` | Open-ended discussions that do not fit a specific application or category. |

---

## Per-application categories

Each application has four dedicated categories. Category slugs use the application name as a prefix (lowercase, hyphenated) to keep them grouped and easy to find.

## Posting guidelines

- **Search before posting.** Check whether a similar discussion already exists.
- **Choose the right category.** Mis-categorized posts may be moved by maintainers.
- **Bug reports in Discussions vs. Issues.** Use a Discussion Bug Reports category when you think you have found an issue but are not yet certain it is a reproducible defect. If it is a confirmed, reproducible bug, file an Issue using the Bug Report template instead.
- **Feature requests.** Use a Discussion Feature Requests category for open-ended ideas. For well-defined proposals, you may also use the Feature Request issue template.
- **Keep titles descriptive.** A clear title helps others find your discussion and helps maintainers triage quickly.
